# storytelling

朴素接地气，从直觉出发，像讲故事一样

本风格遵守 `SKILL.md` 中的标题、图表解读和证据边界硬规则。故事感来自问题逐步展开，不靠悬空口号，也不能省略论文证据。

## 写作特点

- 从问题和直觉切入，不直接讲技术
- 用生动比喻让抽象概念具象化
- 选一个简单例子贯穿全文
- 逻辑递进，层层深入

## 语言风格

- 口语化表达，像和朋友聊天
- 使用"你有没有想过"、"说白了"等引导
- 允许个人见解和 PS 标注
- 避免学术腔调

## 结构特点

- 直觉引入 → 背景知识 → 核心创新 → 实验验证 → 思考展望
- 每个技术点都从"为什么需要"开始
- 用类比连接新旧概念
- 每张图都要接在一个具体问题之后，并在图后用自然段解释可观察到的关系、它对主线的意义和证据边界；不能只靠图注或图前文字完成解释。
- 主标题要先让读者看懂具体对象和反常结果，再让读者产生疑问。标题按“具体动作或场景 → 对不上之处 → 为什么/怎么办”的顺序写；论文缩写和方法名放到副标题，并立即翻译成人话。不要把“错奖”“分开两类反馈”“信用分配”等术语单独当标题，读者必须在标题里看出谁做了什么、哪里出了问题。
- 写标题时先产出 5 个候选，用“对象清楚、冲突具体、论文忠实、记忆点”四项筛选，主标题控制约 18–30 个汉字。优先使用“工具调用做错、回答说对：AI 训练到底该给谁打分？”、“工具做错了却拿高分：AI 训练到底奖励了什么？”这类具体、有冲突但不夸大的句式，再根据论文证据改写。
- 解释公式时用自然语言说清变量代表什么、两部分如何比较或相互作用；默认不把公式源码、变量片段直接放进正文。

## 图表如何融入故事

- **方法框架图**：沿信息流讲清输入、关键环节和输出，再指出它怎样回应前文提出的困难；不要把流程示意图说成实验结果。
- **案例图**：对照图中的不同做法和结果，指出分歧发生在哪一步，以及它如何支持论文的问题设定。
- **实验图或表**：选读者需要的比较，说明趋势、差距或变化，再交代该结果覆盖哪些任务、设置或样本。
- **每张图之后**：紧跟 2–4 句普通正文，先描述图上能直接观察到的内容，再接回本节问题；证据不足以支撑的结论要明确收住。避免机械插入“图表分析：”“关键句：”等标签。

如果图中数值看不清，就描述可核实的方向或关系，不猜数。把观察、论文报告和自己的推断说清楚：图上直接可见的是观察，作者文字中的主张是论文报告，超出两者的解释要标明是可能的含义并限定范围。

## 示例开头

```
你有没有想过这个问题：当我们问 ChatGPT "中国的首都在哪里"，它是怎么知道答案的？

直觉上，我们可能会觉得模型"记住"了这个知识。但实际上，大模型根本没有这样的"记忆模块"——它所有的答案都是**算**出来的。

这种方式有个明显的问题：**大炮打蚊子**。
```

## 适用场景

技术博客、公众号文章、科普分享
