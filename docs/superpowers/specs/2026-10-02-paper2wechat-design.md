# Paper2WeChat 融合仓库设计

日期：2026-10-02
状态：待用户审阅

## 目标

将本机的 `paper-analyzer` 与 `xiaohu-wechat-format` 能力合并为一个可独立安装的 `paper2wechat` skill，并发布在一个 GitHub 仓库中。使用者从论文 URL、arXiv 页面或本地 PDF 开始，按需完成来源获取、论文原图整理、中文文章起草与校验、公众号 HTML 排版与预览，以及明确授权后的公众号草稿推送。

交付范围是单个 skill 和一套辅助脚本。仓库中不得要求安装或调用名为 `xiaohu-wechat-format` 的第二个 skill；原排版器可继续作为内部模块，但所有面向用户的安装说明、提示、命令和配置统一采用 Paper2WeChat 名称。

## 用户流程

1. 用户给出论文 URL 或 PDF。skill 冻结来源元数据，下载论文材料到文章工作目录，并只从该论文的 PDF、HTML 或源文件中选取图片。
2. skill 生成中文 storytelling Markdown，保持论文结论可追溯，图片引用使用文章目录内的相对路径，并生成来源、尺寸和哈希清单。
3. skill 运行论文文章结构校验及中文标点检查，使用用户选择的主题生成公众号兼容 `article.html` 和完整 `preview.html`；默认主题沿用当前工作流使用的 `bytedance`。
4. 当且仅当用户明确要求“推送”时，读取本地配置的公众号凭据，上传文章图片和论文第一张最终图片作为封面，向公众号草稿箱提交；不执行正式发布。
5. 产物保留在每篇文章独立的输出目录，调试文件、下载源文件与最终用户可读产物分开管理。

## 融合范围与能力保留

### 论文分析能力

保留来源冻结、storytelling 写作要求、标题候选评分、原论文图挑选、图片 manifest、Markdown/HTML 结构校验、公式与代码内容边界、文章目录布局和论文辅助提取工具。论文默认不启用代码分析，除非用户明确要求。

### 公众号排版能力

保留现有 formatter 的主题选择和画廊、WeChat 内联样式 HTML、独立预览页、Markdown 图片与 Obsidian wikilink 图片处理、结构/语义标记支持、LaTeX 图片渲染辅助、中文标点修复、输出格式选项、主题配置和相关模板。包含当前全部主题文件，不仅限于默认主题，确保合并不缩减现有可选能力。

### 草稿推送能力

保留微信公众号草稿 API 工作流、正文图片上传、封面上传、标题/作者/来源链接、合集参数、dry-run/确认选项、公式发布门、错误诊断和可选调试输出。推送默认只创建草稿，不能直接发布到公众号。

## 仓库与配置结构

仓库名和单一 skill 名称均为 `paper2wechat`。顶层 `SKILL.md` 描述唯一工作流；`scripts/` 收纳论文分析、格式化、标点检查、校验、封面与发布辅助脚本；`themes/` 和 `templates/` 保留完整现有素材；`styles/` 保留论文叙事风格定义；`config.example.json` 展示配置格式；`outputs/` 仅用于本地生成文件且在 Git 中忽略；README 提供安装、依赖、配置、使用和安全说明。

代码通过仓库相对路径定位主题、模板和辅助脚本，不依赖 `C:\Users\...`、`~/.codex/skills/...`、Claude 或特定个人目录。提供单个本地 `config.json` 配置入口，并在 `.gitignore` 中忽略该文件、API 密钥、临时文件、Python cache、输出文章和调试材料。公众号与 LLM 凭据不写入仓库，不在日志中输出 access token 或 secret。第一次安装不会要求配置微信账号；只做分析和排版时可不配置凭据。

## 命名与品牌

不再使用 `xiaohu-wechat-format` 作为 skill、默认输出目录或 README 中的产品名称。统一使用 Paper2WeChat。历史函数和资源标识只在为兼容用户主题、配置或输入内容所必需时保留；具体保留项需在实现过程中审计并记录，不能因品牌改名破坏格式器兼容性。

## 验收标准

- 仓库中只有一个顶层 `SKILL.md`，名称为 `paper2wechat`；安装说明只展示一个 skill。
- 全部来源文件和资源均来自两个本地 skill 目录；不包含个人生成的论文文章、下载论文、真实配置、账号密钥、缓存或私人主题素材。
- 当前 formatter 的所有主题 JSON 与模板均被保留，且名称能被主题加载器识别。
- formatter 原有 CLI 选项和 publisher 原有 CLI 选项均经过盘点；合并后要么保持可用，要么有经用户认可的清晰迁移说明。不得静默删除任何功能。
- Paper2WeChat 从论文 URL 输入到 Markdown 校验、HTML/预览生成可在未配置微信公众号密钥时运行；没有明确推送请求时不得调用写入公众号的 API。
- 图片引用与 manifest 一致、全部可解析到本篇文章本地图片；推送时图片计数、封面和输出目录均可验证。
- 公开仓库没有个人绝对路径、访问令牌、AppSecret、API key 或用户历史产物；密钥只从被忽略的本地配置或环境变量读取。
- 提供可重复运行的基础检查，覆盖 Python 语法、主题文件解析、格式器输出、论文 Markdown/HTML 校验、推送 dry-run、配置缺失和错误凭据路径。

## 不在本次范围

不创建或公开 GitHub 远端，不配置公众号账号，不生成额外的网络封面图，不上传历史文章和 PDF，不移除或修改当前用户目录中的两个已安装 skill。待本地仓库完成并审阅后，再决定是否创建公开 GitHub 仓库。

开源许可证由用户最终选择。仓库实施前可先将许可证选择列为发布前检查项；未确认前不添加会授予特定许可的 `LICENSE` 文件。
